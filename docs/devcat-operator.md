# DevCat Yandex MCP operator guide

Target: CatVPS, one default account plus an explicit additional-account allowlist, fork commit pinned in `/opt/yacli-devcat/releases/<commit>`. The service example is in `ops/devcat-yandex/`. The public connector must use the existing managed Secure MCP Tunnel; DevCat mode always binds only to a loopback address. On the current CatVPS deployment the listener is `127.0.0.1:8797` because `8787` is already used by another MCP. For the managed tunnel path, set `YACLI_DEVCAT_TRUST_SECURE_TUNNEL=1` and omit the inner MCP bearer so ChatGPT can discover tools through the tunnel. Without that explicit flag, DevCat mode still requires the Bruce-vault MCP bearer. Do not point a public reverse proxy at the listener. OAuth credentials remain canonically in Bruce Secrets on BruceVPS; CatVPS accesses those exact keys through the existing private `/usr/local/libexec/catvps-vault` helper. Do not create another secret store or local fallback.

## Prepare

1. Use the DevCat-owned Yandex OAuth app with confirmation-code + PKCE support. The registered redirect URI must match yacli's verification-code URI. The unit records client ID `7caac656017c4cac84c193cef1e02a34`. Its OAuth login is configured to request broad Mail `mail:imap_full` + `mail:smtp` and Disk `cloud_api:disk.info`, `cloud_api:disk.read`, and `cloud_api:disk.write` scopes.
2. For OAuth, run `yacli login mail` and `yacli login disk` separately under the DevCat environment (`YACLI_DEVCAT_MODE=1`, configured account, roots, client ID, vault helper, and `YACLI_CONFIG_DIR`). The owner opens the generated Yandex authorization URL and enters its one-time code directly in the terminal. The CLI exchanges the code and writes each token directly to the exact Bruce vault key named in `accounts.toml` using the configured helper's `exists`, then `put` or `replace` interface. Production sets `YACLI_DEVCAT_VAULT_HELPER=/usr/local/libexec/catvps-vault`. That private helper provides exact-key access from CatVPS to canonical Bruce Secrets; it is not another store. The CLI does not create `credentials.toml` or print token values. Do not paste values into chat, repository files, CLI arguments, service environment, or logs. Check key presence by exit status, never by printing a token. Yandex app consent remains owner-only. `DEVCAT_YANDEX_MCP_BEARER` may remain provisioned for rollback or a direct bearer-protected loopback deployment, but the managed Secure MCP Tunnel profile does not require it when `YACLI_DEVCAT_TRUST_SECURE_TUNNEL=1` is explicitly enabled.
3. Copy `accounts.toml.example` to `/var/lib/yacli-devcat/config/accounts.toml`, add each approved account with its own service enablement and exact vault key references, and set mode `0600`. `YACLI_DEVCAT_ACCOUNT` is the default account; optional `YACLI_DEVCAT_ALLOWED_ACCOUNTS` is a comma-separated exact allowlist for additional accounts. Requests for any other account fail closed. The file stores only account metadata and vault key names. Do not install `credentials.toml` or a production `.env`.
4. Build `cargo build --locked --release` from this fork's reviewed commit in the supported CI/build environment. Install the resulting binary and the MIT `LICENSE` under `/opt/yacli-devcat/releases/<commit>`, with `current` symlink pointing to the release. Fill in the owned client ID in the unit, install it to `/etc/systemd/system/yacli-devcat.service`, then `systemctl daemon-reload && systemctl enable --now yacli-devcat`.
5. Probe `curl --fail http://127.0.0.1:8797/healthz` and verify the listener with `ss -lnt`. In bearer-protected mode, an unauthenticated `POST /mcp` must return 401. In managed-tunnel mode with `YACLI_DEVCAT_TRUST_SECURE_TUNNEL=1`, an unauthenticated loopback `initialize` must succeed so the tunnel can discover `tools/list`; the process must still be bound only to loopback. Run the managed Secure MCP Tunnel health/readiness checks before registering or refreshing the ChatGPT connector. If the tunnel forwards a browser `Origin`, set `YACLI_DEVCAT_ALLOWED_ORIGINS` to the exact trusted origin; never use a wildcard.

## Capabilities and review

Для выпуска #723 текущая production-служба должна получить точный набор возможностей из ops/devcat-yandex/yacli-devcat-capabilities.conf: mail.mutate включает review-gated папки, черновики, перенос/копирование, флаги и локальный runner правил; mail.delete разрешает только удаление проверенной пустой пользовательской папки; disk.delete перемещает в Корзину без безвозвратного удаления; contacts.read/write открывают CardDAV-инструменты, но сами по себе не подключают адресную книгу. Override также задаёт `YACLI_DEVCAT_DOWNLOAD_ROOTS=/var/lib/yacli-devcat/downloads`, уже предусмотренный безопасный локальный каталог для проверенных скачиваний; Disk provider roots, OAuth scopes, `disk.publish` и Calendar не включаются. Туннель не меняется.

Применяйте override только после успешной изолированной приёмки кандидата и перед запуском ops/devcat-yandex/install-verified.py --apply, иначе post-deploy tools/list намеренно не подтвердит полный каталог. Оператор с действующим привилегированным маршрутом устанавливает файл командой install -D -o root -g root -m 0644 ops/devcat-yandex/yacli-devcat-capabilities.conf /etc/systemd/system/yacli-devcat.service.d/20-yacli-723-capabilities.conf, затем выполняет systemctl daemon-reload и перезапускает только yacli-devcat.service. До переключения бинарника проверьте systemctl show yacli-devcat.service -p Environment без публикации полного вывода. При откате восстановите предыдущий drop-in (включая прежнее значение `YACLI_DEVCAT_DOWNLOAD_ROOTS`) и перезапустите только ту же службу; Secure MCP Tunnel остаётся запущенным.

`YACLI_DEVCAT_CAPABILITIES` controls MCP tools independently of OAuth consent. Production enables `mail.read`, `mail.send`, `disk.read`, and `disk.write`; the broad OAuth grant does not expose additional tools. With `mail.send`, the MCP profile exposes send, reply, and forward tools; risky calls require dry-run plus one-time review. `mail.forward` also binds the review to a digest of the selected source message and attachment bytes. Нативные файлы ChatGPT теперь принимаются также инструментами `mail.reply` и `mail.forward`; SHA-256 каждого файла включается в привязку review. `mail.read` exposes bounded paginated `yacli.mail.draft.list`, limited to the IMAP mailbox advertised with `\Drafts`. `mail.mutate` exposes unsent draft creation/update, Trash move, folder creation, single-message copy/move, and read/starred flag changes; every mutation requires a dry-run plus a one-time five-minute review digest. Draft creation appends one `\Draft` message to the provider-advertised `\Drafts` folder. `yacli.mail.draft.update` binds review to source RFC822 SHA-256 and UIDVALIDITY, appends a replacement with `\Draft`, verifies the source, then moves the old draft to advertised Trash. Если APPEND возвращает ошибку, инструмент ищет только созданный им уникальный Message-ID и продолжает операцию лишь при наличии ровно одной подтверждённой версии; APPEND автоматически не повторяется. Если новую версию подтвердить нельзя, исходный черновик остаётся на месте, а сообщение об ошибке требует проверить Drafts и Trash перед новой попыткой. Neither draft tool sends mail or permanently deletes it. Sending an existing draft is not implemented. Move can target an operator-selected Trash or Spam folder, but does not permanently delete messages or expose separate spam actions. Отдельная возможность `mail.delete` разрешает удаление только явно указанной пустой пользовательской папки: сервер отклоняет системные папки, папки с подпапками и папки с письмами, затем повторно проверяет папку перед IMAP DELETE. Операция необратима и выключена, пока оператор явно не выдаст `mail.delete`; живую проверку проводить только на специально созданной тестовой папке. `contacts.read` independently exposes `yacli.contacts.list`, `yacli.contacts.search`, and bounded `yacli.contacts.export` only for accounts with `contacts.enabled = true` and a separate `contacts.credential_ref`. CardDAV uses a Yandex Contacts app password, not Mail/Disk OAuth. Store only its key reference, for example `vault:DEVCAT_YANDEX_CONTACTS_DEDTS`; never place the password in `accounts.toml`. `contacts.write` exposes import/create/update/delete behind dry-run plus a one-time five-minute review digest; import is limited to 50 cards from an allowed local file and export is capped at 50 cards/1 MiB; updates and deletes also require the current strong ETag and fail on provider conflict. `disk.write` also exposes copy/move/restore from Trash behind dry-run review. Separately gated `disk.delete` only moves an explicit resource to Trash (`permanently=false`); there is no API tool for permanent deletion or emptying Trash. Trash listing uses `disk.read`. Private upload/download streams files instead of returning full contents; `disk.read` remains limited to 1 MiB base64. Downloads from Disk, exported Mail attachments, and original `.eml` messages can write only beneath `YACLI_DEVCAT_DOWNLOAD_ROOTS`, which must be a dedicated directory owned by the service account; downloads and `.eml` export require dry-run review and reject symbolic-link targets. Upload sources and Mail attachment paths require `YACLI_DEVCAT_UPLOAD_ROOTS` and must resolve to regular files under a configured local root. Per-user share permissions are not supported by the current local tool surface. Publication remains disabled because `disk.publish` is absent. Инструменты удаления писем и безвозвратного удаления файлов не зарегистрированы. Disk paths must be explicit and inside `YACLI_DEVCAT_DISK_ROOTS`; percent escapes, alternate separators, dot segments, Unicode compatibility normalization, and empty segments are rejected. The example unit creates the local transfer roots with mode `0700` in `/var/lib/yacli-devcat`.

`yacli.mail.checkpoint` read-only получает `UIDVALIDITY` и `UIDNEXT` выбранной папки. `mail.copy`, `mail.move`, `mail.flags`, `mail.bulk` и `mail.special_folder` требуют UIDVALIDITY из списка и сверяют его до изменения. Для `mail.reply`, `mail.forward` и других UID-инструментов epoch guard пока не добавлен; после смены UIDVALIDITY используйте только свежие результаты списка.

If the granted OAuth scopes change, repeat the matching OAuth login. MCP capability flags govern exposed tools; OAuth scopes govern what a token could authorize at the provider. Neither one expands the other.

## Локальные правила Mail

`yacli mail rules add` сохраняет правило в отдельный `mail-rules.toml`, выключенным по умолчанию. Условия — точные account alias и IMAP mailbox, плюс одно или оба подстрочных условия From/Subject; совпадение проверяется без учёта регистра. Доступны только отметки прочитано/непрочитано и избранное/снять избранное. Создание, изменение, включение, выключение, просмотр, удаление, запуск и аудит доступны через CLI (`yacli mail rules --help`). MCP публикует `yacli.mail.rules.list`, `.audit`, `.preview` (требуют `mail.read`) и `.configure`, `.run`, `.undo` (требуют `mail.mutate`). Это локальный IMAP runner, не серверный фильтр Яндекса.

Перед первой ручной обработкой сохраните baseline через `yacli mail rules baseline ID` либо через MCP `.configure` с `operation=baseline`, используя dry-run/review. Baseline фиксирует UIDNEXT, поэтому более старые письма пропускаются. `.preview` и `run dry_run=true` только читают IMAP и не меняют файлы; без baseline они возвращают `baseline_required`. Пакет ограничен 50 UID; digest находится во вложенном объекте `preview.review_sha256` или `results[].preview.review_sha256`. Чтобы применить пакет через CLI, передайте его с `--apply --review-sha256`. В DevCat MCP нужно три вызова: сначала `.preview` и проверка plan digest; затем `.run` с `dry_run=true`, тем же account/rule и `plan_sha256`, чтобы получить одноразовый внешний MCP `review_sha256`; затем `.run` с теми же account/rule/plan, `dry_run=false` и внешним review digest. Если при повторном preview изменился вложенный plan digest, остановитесь и начните review заново. Для undo используйте `.undo` preview, затем повторный `.undo` с `dry_run=true` и plan digest для получения внешнего review, затем примените с теми же аргументами и `dry_run=false`. Следующие страницы обрабатывайте отдельными запусками. `yacli mail rules poll` выполняет один ограниченный цикл только для явно включённых правил; при первом poll он безопасно устанавливает baseline без обработки старых писем. Оператор может настроить свой systemd timer или другой локальный scheduler на этот вызов; этот релиз сам не устанавливает timer и не держит IMAP IDLE соединение. В DevCat автоматическое применение требует явно выданной возможности `mail.mutate`. Не включайте правило до проверки его preview.

При запуске runner сначала сохраняет pending пакет, затем сверяет UIDVALIDITY и отпечатки писем перед каждой флаговой мутацией. Ошибка оставляет pending для безопасного повтора. `yacli mail rules audit` показывает content-free журнал; `yacli mail rules undo RUN_ID` строит preview отката, а `--apply --review-sha256` применяет его, только если текущее целевое состояние флага не изменилось. Сброс/удаление запрещены при pending. Правила, состояние и аудит используют отдельные файлы `mail-rules.toml`, `mail-rules-state.toml` и `mail-rules-audit.toml`; runner не читает и не переписывает `/home/codex/mail-watch/state.json`. Совместимость с legacy watcher требует отдельной проверки и миграции владельцем. MCP `.configure` меняет только локальную конфигурацию правил и требует review; `poll` пока доступен только CLI.

The Yandex Mail REST API is a separate, tariff-gated route for labels, server-side filters, thread operations, and additional mailbox actions. It requires explicit OAuth scopes such as `mail:filters.read`/`mail:filters.write`, `mail:labels.read`/`mail:labels.write`, and `mail:messages.read`/`mail:messages.write`; the current IMAP/SMTP OAuth token is not evidence of those grants. Do not add these scopes or wire a REST credential into production without the account owner's consent and confirmation that the account has an eligible paid Yandex 360 subscription. Until then, use only the existing approved IMAP/SMTP and Disk scopes. See the official [Mail API overview](https://yandex.ru/dev/yandex-360/mail/ru/) and [OAuth access guide](https://yandex.ru/dev/yandex-360/mail/ru/access).

Risky tools require two calls: first `dry_run=true`; inspect the review output and retain `review_sha256`; then repeat the identical arguments with `dry_run=false` and the returned `review_sha256`. The digest also binds local source file bytes and, for `mail.forward`, the reviewed source message and attachment bytes; it expires after five minutes and is consumed once. The service emits content-free JSON mutation audit records to the systemd journal (`journalctl -u yacli-devcat`). The general yacli activity store is disabled in DevCat mode. Restrict journal access to operators.

`yacli.disk.read` returns at most 1 MiB as base64; larger files need a separately reviewed transfer workflow. Mail read/search and Disk list/read do not require mutation capabilities. Calendar, dashboard, activity undo, prompts, resources, and other broad upstream MCP surfaces are disabled by the DevCat profile.

## Update and rollback

Build and test the next pinned fork commit, install a new release directory, save the old `current` target, switch the symlink, and restart. Re-run loopback health, the expected auth behavior for the selected mode, tool list, read-only Mail search/read, and Disk list/read. For managed-tunnel mode, also confirm tunnel readiness no longer reports upstream 401 and that ChatGPT refresh discovers the tool catalog. For rollback, restore the old `current` target and restart. Keep the old binary and service unit until the new read canary passes. Do not use upstream `yacli update` on this service.

## Live canary boundary

After OAuth consent and vault presence, use a dedicated test mailbox message and a dedicated file under the allowed Disk root to prove Mail search/read and Disk list/read. Only if mutation capabilities are intentionally enabled, create a new test object inside that root and use dry-run + review digest before publish/send/unpublish. Never mutate existing user data as a canary. If credentials are absent, report exactly the missing app registration/consent/vault-key gate and leave the service unexposed.

## Hosted Yandex 360 MCP fallback for dedts only

This is an optional alternative route and does not change the local yacli service or enable hosted tools. Official endpoints are Mail `https://mcp.360.yandex.net/v1/mail/mcp` and Disk `https://mcp.360.yandex.net/v1/disk/mcp`; each is a separate HTTP streaming MCP server. Configure separate named entries in the approved ChatGPT MCP settings UI, with `Authorization: OAuth <owner-provided token>` stored as a protected secret field. The owner must obtain the Mail and Disk OAuth tokens while signed into the exact `dedts` Yandex account and review the requested grants. Do not send tokens to chat, terminal commands, GitHub, or logs, and do not store them in this repository, `accounts.toml`, or the service environment. No token has been obtained as part of this task.

After the owner completes OAuth and saves the protected entries, call `tools/list` on each endpoint and perform only read-only Mail and Disk canaries before reporting the hosted connector as connected. Until those checks succeed, leave the route unverified. The official hosted services are labeled preview. Hosted Mail can create/update drafts and move/label/trash messages, but cannot send; the user sends a reviewed draft in Mail. Hosted Disk supports public access settings and moving/copying/deleting to trash, not granting permissions to individual users. Eligibility depends on an active paid personal Yandex 360 subscription or an organization's Yandex 360 business subscription. See the official [Mail MCP guide](https://yandex.ru/dev/yandex-360/mcp/ru/mail), [Disk MCP guide](https://yandex.ru/dev/yandex-360/mcp/ru/disk), and [MCP overview](https://yandex.ru/dev/yandex-360/mcp/ru/).
